EEG lab setup
=============

The lab build is the shipping game with config/eeg_lab.yaml on top:
markers on, trigger box required, FRN bytes in Chords and Force Pilot.
The games look, sound and give feedback as on every other build. The
Reaction card is the lab's own SRT task (Welber's PsychoPy script,
replicated trial for trial). The Lab session plays it once, first in
both orders, in place of the study's two Reaction blocks, with a
response byte per trial, and leaves out Muscle Memory: the SRT's recall
question tells the participant a sequence was there, so a later Muscle
Memory score would not pool with the study's. About 48 minutes from
login, the SRT about 15 of them. The folder that goes to the lab is
EEG_Lab (FingerRehab-EEGLab.zip on CI); the exe loads the yaml beside
it, so a game update is a lab update. To rehearse on any PC, run
developer\EEG simulator.cmd first.

The chain: game -> USB -> the lab's marker, an Arduino on COM10 at
9600 baud (box: arduino in eeg_lab.yaml; a NeuroSpec MMBT-S trigger box
works the same way) -> the trigger cable -> BioSemi ActiveTwo USB
receiver -> ActiView. One byte per write sets the marker's eight lines,
trigger inputs 1 to 8, the low byte of the Status channel. Nothing
comes back: the game only sends.

At the lab PC
-------------
1. Plug the marker in, and the hand boards if used, before pressing
   Run. With a NeuroSpec MMBT-S box the switch beside its USB socket
   should read P (Pulse Mode: the box holds each code 8 ms); if it
   reads S, set pulse_ms: 10 and box_mode: simple in eeg_lab.yaml.
2. Start ActiView. The trigger low byte reads 255.
3. Open run_in_psychopy.py in PsychoPy Coder and press Run (or
   double-click Finger Rehab.exe); close PsychoPy's first-start tips.
   The low byte drops to 0 the moment the game opens the port. If the
   box is not on COM10 the game opens on a port list: click the
   marker's port (unplug it and Scan again to see which entry goes),
   then Continue; the choice is saved in eeg_lab.yaml. The marker is an
   Arduino, so the game can take it for a hand board: Settings, EEG box
   lists it as "hand board now", and clicking it moves it to the
   markers. Settings, EEG box also reconnects a box that dropped out.
4. If Windows refuses the unsigned exe (Smart App Control on Windows
   11), the launcher runs the same game from source/ under PsychoPy's
   own Python (3.10 or newer). The first time it installs what
   PsychoPy lacks into python_packages/, which needs the internet once;
   each computer gets its own subfolder there.
5. Log the participant in. The menu shows the recording's name, for
   example "EEG: record ActiView as P07_2026-09-24.bdf in
   EEG_Lab/sessions/eeg". Start ActiView's recording with exactly that
   name, then pick the first game. With ActiView on the game PC, save
   it in that folder and the line turns to "EEG recording ... is in
   ..."; with ActiView on its own EEG PC, save it there under that name
   and the line stays up all session. A second login the same day gets
   _2, _3 and so on.
6. Play. Keep Test Mode off (Settings, Data). P pauses; Esc twice ends
   one game. A red "EEG markers lost" means the box dropped out: finish
   that game, then Settings, EEG box, and pick it again.
7. End the session with Esc on the game menu, End session. Then stop
   ActiView's recording.
8. Never set 1200 baud: it resets the box off the bus, and the game
   refuses eeg.baud 1200. Leave the port's settings alone.
9. Keep vsync on, or visual markers lead the screen by an unknown
   amount. Write the panel's refresh rate on the session sheet: every
   SRT block records monitor_hz and vsync in metadata.json, and about
   120 Hz on a 60 Hz panel means the window ran without vsync.
10. Reaction opens on its setup screen; keep it turned away from the
   participant. Pick the timing group (or a saved setup) and START,
   saying the group aloud and checking it against the session sheet:
   the screen opens on the group last picked on this computer, even
   after a new lab folder is copied in. The hands come from login (two
   hands, as the lab's own studies ran it, need both boards or the
   keyboard). Leave musical experience blank and ask about formal
   musical training after the task, on the session sheet: a question
   about music before the task points at the tones. The task is the
   old script's, drawn as the script drew it: grey squares on a black
   page at the script's sizes, colours and words (srt.look: lab;
   srt.look: app gives the game's finger cards), one 30 per flash and
   one response byte per trial, SPACE between blocks, the recall at the
   end, and the script's three CSVs beside trials.csv. After the
   recall, ask "Did you notice anything about the order of the lit
   cards? If so, what?" and write the answer word for word on the
   session sheet (srt_noticed and srt_report on the intake sheet). The
   answer on screen to the recall question is not recorded.
11. Everything lands in sessions/ beside run_in_psychopy.py: a dated
   folder per game with trials.csv, raw.csv (an eeg row per marker,
   intended and actual send time), metadata.json (its eeg section has
   the port, pulse widths, code map, latencies, failures and which
   recording the game belongs to), events.tsv with events.json and
   markers_codes.csv, plus rehab.log. Take the whole sessions/ folder
   home with the .bdf from the EEG PC, put the .bdf in sessions/eeg
   beside the games, and merge the folder into the project's
   sessions/: the notebook lists each game's recording as present or
   missing.
12. Settings changes at the lab last until the game closes; every
   launch starts from eeg_lab.yaml again, except the trigger box port.
13. Flash firmware and change sensor addresses from the exe's Settings:
   the source/ copy carries no avrdude.

Testing the lab build on a Mac, no box
--------------------------------------
scripts/virtual_trigger_box.py stands in for the box: a pseudo-terminal
the game opens like any serial port, which records every byte. It
starts the lab folder's source/ under PsychoPy's own Python with
eeg_lab.yaml, the way run_in_psychopy.py does. Play, then close the
game: the script lists the bytes it received against the markers each
block logged in raw.csv and writes the byte log to
EEG_Lab/sessions/eeg/virtual_box_<time>.csv.

    python3 scripts/virtual_trigger_box.py
    python3 scripts/virtual_trigger_box.py --box-only   just the box

The first time, run run_in_psychopy.py once from PsychoPy Coder so it
installs the packages the game needs. Delete the test sessions from
EEG_Lab/sessions before the folder goes to the lab.

What the Status channel shows
-----------------------------
- 240 once as the login session's first game starts, 241 once at
  End session or app exit, both outside any block.
- Each block: 200+mode at the start, 20 at GET READY, 220+mode at the
  end (219 if abandoned).
- Each stimulus a 30 to 38 (40 or 41 in pattern blocks, 50 or 51 for
  a syllables option set, 52 for its late prompt buzz, 53 for the
  four words of a speed trial), each press
  100 to 131. In the lab build's SRT blocks every trial ends with 100
  plus the lane for a correct press, 110 plus the lane for a wrong
  one, 120 plus the lane for an anticipation or 130 for a miss, sent
  at the trial's end with the press time as t_event in raw.csv, so
  response epochs are re-aligned to t_event. Every code is held until
  the first frame at least 8 ms later (8 to 17 ms at 60 Hz, 16 to 35
  samples at 2048 Hz), then 0. The box's LED flashes on odd codes
  only.
- Pauses are 242 and 243.
- If the box dies mid-session the game keeps going: three failed
  writes, one reopen, then the HUD says "EEG markers lost" and
  metadata marks the block degraded. Behaviour stays valid; ERPs from
  that point do not.

Codes (finger_rehab/hardware/eeg_trigger.py, CODES, version 1.7)
----------------------------------------------------------------
 20  GET READY onset (not in srt blocks, which have no card: they
     open on the lab script's own SPACE screens)
 21  reaction: wait armed (CNV S1)
 22  rhythm: leading buzz, at the STIM command. In the study battery
     (tactile_mode on_beat) it leads the beat's own byte by the
     motor's rise only, about 74 ms; in free play (lead mode) by
     about 424 ms (350 lead plus 74 rise, then adapting to the
     player). The beat's byte is then 31.
 23  Force Pilot: run start
 24  Force Pilot: section edge, the run's end included
 25  reaction: virtual onset of a catch trial
 30  stimulus, screen only            31  screen + tone
     (in an SRT block 30 is the red flash with its tone, as the old
     script sent it)
 32  screen + buzz                    33  screen + buzz + tone (default)
 34  uncued                           35  tone only
 36  buzz only                        37  buzz + tone
 38  Buzz Hunt: the buzz is the stimulus, one per trial at its first
     pulse; scored trials write no response byte
 40  pattern block, sequence item     41  pattern block, random item
 50  syllables option set, first attempt
 51  syllables option set, word returned after a miss (four written
     options, nothing names the finger: never pool with the 30 band)
 52  syllables prompt buzz on the right finger, at the STIM command,
     when a set is still unanswered at 0.6, 0.75 then 0.9 of its fall
     (one step later per word for each answer found alone, then no
     prompt), never before the reader's own median answer time plus
     300 ms; a press after it is a prompted answer. In a syllables
     block a press inside a set's 0.2 s spawn lockout is 120 + lane
     at the press (no 130 follows it), and a press with no set open
     is 131
 53  syllables speed trial: the four words, after the flashed word
     and its 150 ms mask (the flash itself has no byte; its length is
     expo on the row)
100+lane  correct press               110+lane  wrong finger (lane pressed),
                                          sent at that press; the first
                                          one of a trial is its response
120+lane  false start                 130  timeout (never epoch on it)
131  press with no trial active
140  hit  141  miss. Written with the outcome flash, in the modes
     eeg_lab.yaml names (reaction, chords, force_pilot). 142 (near)
     only comes with the delayed ring display (ui.feedback_style:
     neutral, ui.feedback_delay_ms: 800), which the lab no longer
     uses. Force Pilot has no presses: its 141 is written on the
     frame the craft leaves the corridor and stalls, at most once a
     second, with or without the exit buzz. In Chords the byte
     follows the chord's outcome, not the first finger's speed: 141
     for a miss or a chord with a finger missing, 140 otherwise. Echo, if it
     is ever named, writes its own byte at the trial close and only
     in the immediate style (feedback_delay_ms 0): under a delay
     nothing is drawn for an echo trial, so no byte leaves.
200+mode  block start   219  abandoned   220+mode  block end
     mode ids: reaction 0, classic 1, adaptive 2, rhythm 3, mirror 4,
     pattern 5, chords 6, syllables 7, force_pilot 8, buzz_hunt 10,
     echo 12, srt 13 (9 retired, 11 reserved)
240  session start   241  session end   242  pause   243  resume
244  rest start      245  rest end

Lanes: 0 to 3 index to little on a one-hand block, whichever hand
(the hand column on the row and in events.tsv says which); with both
hands selected, right 0 to 3 and left 4 to 7. Chords
write one 33 and one response byte per chord, not per finger. Mirror
writes one 33 per pair and one 100+lane per hand, each sent at that
hand's own press. Rhythm's 130 lands when the miss
window closes, inside the next note. Force Pilot runs carry 23 and 24
and no stimulus or response bytes. A Force Pilot run paused part way
restarts from its card: the 23 and 24 bytes it sent before the pause
belong to no trial row (raw.csv holds a run_restart event where it was
cut), so drop the bytes from the last 23 before that event up to it.
The notebook's audit sets them aside the same way.

For the analysis
----------------
- Every eeg row in raw.csv carries code, t_event (the crossing sample,
  or the flip), t_wire (when the byte left), delayed, failed, dropped
  and name. A response byte trails its press: the press sample reached
  the laptop up to about 20 ms late in a USB burst, and the byte waited
  up to one frame after that.
- events.tsv (BIDS columns onset, duration, trial_type, value, sample,
  lane, hand, t_event, t_wire, delayed, failed, dropped,
  press_offset_ms, onset_offset_ms) is on the game's clock, onset from
  the block's first force sample. Align by matching inter-marker
  intervals to the Status channel, then shift.
  eeg.amplifier_rate_hz in eeg_lab.yaml fills the sample column.
  finger_rehab.hardware.eeg_trigger.export_events(folder) rebuilds the
  three files for any session folder.
- Response-locked epochs: press_offset_ms is how far the press sample
  sits from its byte on the board's own 5 ms clock, the USB bursts
  and the frame wait taken out; onset_offset_ms is the same for where
  the push began, found on the force trace by the notebook's onset
  detector. Both are negative. Lock at the byte's Status sample plus
  the offset, less the box's fixed delay. The 30 percent press point
  sits a median 50 ms after the onset (pilot presses, 7 October 2026),
  and further on slow or light presses, so lock motor potentials
  (ERN, LRP, readiness) to the onset and keep the press lock as the
  check.
- Shift stimulus-locked epochs by eeg.marker_offsets_ms from
  metadata.json: the screen follows the byte by latency.visual_ms
  (20), the tone by latency.tone_ms (12), a felt buzz by
  latency.buzzer_ms (45). Datasheet estimates until the rig is
  measured (latency.measured false); scripts/latency_check.py has the
  bench procedure. Put the medians in the config and in the methods.
- For FRN work drop rows with error_type timeout, device_drop or
  no_signal; 142 (half ring, ring display only) is neither a win
  nor a loss. Recordings
  made before 24 September 2026 could carry a 140/141 within one frame of
  the block-end byte: leave that one out. Do not switch
  ui.feedback_style mid-study: it moves the feedback epoch.
- MNE: mne.io.read_raw_bdf(stim_channel="auto") then
  mne.find_events(raw, mask=255, mask_type="and"). EEGLAB: File,
  Import event info, from ASCII file, fields latency type duration.
- Against Welber's old SRT script: it wrote one 30 per flash and
  nothing else, and the Reaction card (srt blocks, 213 to 233) sends
  the same 30; the lab build adds the response bytes above, which an
  epoch on 30 never sees. The other games put the cue condition in
  the byte, so epoch them on the 30 band, not the literal 30. The old
  script wrote bytes(chr(code), 'UTF-8'), two bytes for anything above
  127, and held the line 1 to 4 ms; this game writes bytes([code]) and
  holds it to the first frame at least 8 ms later. Recordings made
  under the old prototype map (30 = miss, 11 to 18 stimulus) must not
  be pooled with these.

Validate once before the first real recording. In a Python shell on
the lab PC, `import serial; s = serial.Serial("COM10", 9600);
s.write(bytes([30]))` shows one 30 in ActiView. Then run one Reaction
block: the intervals between stimulus bytes in the Status channel must
match the t_wire intervals in raw.csv to within one sample plus 1 ms.
Confirm the ActiView sampling rate with Welber and put it in
eeg.amplifier_rate_hz.

That checks the wire, not the screen or the speaker, and only a light
sensor and a microphone show those delays (Bridges et al. 2020, PeerJ
8:e9414). Time them once, on the lab PC with its own monitor: set
srt.photodiode_patch: true in eeg_lab.yaml for this run only (a patch
in the bottom-left corner on flash frames; a sensor on a card would
read that card's own brightness), put the light sensor on that corner and a microphone
(or a split of the audio output) on two of the amplifier's auxiliary
inputs, and play the SRT's practice block with markers on (Esc after
it). For each 30, the delay to the light change and to the tone's
onset is the visual and the tone delay: report the mean, SD and
range, write them into the lab PC's latency profile (latency.visual_ms
and latency.tone_ms, so metadata.json carries them), check monitor_hz
against the panel, and set srt.photodiode_patch back to false. Leave
srt.tone_lead_ms at 0, the script's behaviour, unless the lab wants
the tone with the flash; then it is the measured tone delay minus the
visual delay.
