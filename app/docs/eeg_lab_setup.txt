EEG lab setup
=============

The lab task is the shipping game with config/eeg_lab.yaml loaded on
top: markers on, trigger box required, fixed 2.5 s reaction foreperiod
with a visible Ready cue, no music in Force Pilot, neutral feedback
(one ring glyph 800 ms after the press, no words, no chime), FRN bytes
in reaction, chords and Force Pilot. The folder that goes to the lab is
EEG_Lab at the top of the project (FingerRehab-EEGLab.zip on CI):
Finger Rehab.exe, eeg_lab.yaml, run_in_psychopy.py, README.txt, a
source/ copy, and sessions/ with an empty eeg/ folder for ActiView's
recordings. The exe loads the yaml beside it on its own, so a game
update is a lab update.

The chain: game -> USB -> NeuroSpec MMBT-S trigger box (orange Tobii
Pro case, a virtual COM port) -> D-Sub 25 to D-Sub 37 cable -> BioSemi
ActiveTwo USB receiver -> ActiView. One byte per write sets the box's
eight lines, which land on trigger inputs 1 to 8, the low byte of the
Status channel. Nothing comes back: the game only sends.

At the lab PC
-------------
1. Plug the box in, and the hand boards if they are used, before
   pressing Run. The switch beside the box's USB socket should read P
   (Pulse Mode: the box holds each code 8 ms and resets itself). If it
   reads S, set pulse_ms: 10 and box_mode: simple in eeg_lab.yaml.
2. Start ActiView. The trigger low byte reads 255.
3. Open run_in_psychopy.py in PsychoPy Coder and press Run (or
   double-click Finger Rehab.exe). PsychoPy's first start shows a tip
   and a list of changes: close both. The low byte drops to 0 the
   moment the game opens the port. If the box is not on COM10, the
   game opens on a list of ports instead of the login: click the box,
   not the entry named USB-SERIAL CH340 (that is the hand board; unplug
   the box and press Scan again to see which entry goes), then
   Continue. The choice is saved in eeg_lab.yaml. Settings, EEG box, changes it later or
   reconnects a box that dropped out.
4. If Windows refuses the exe (it is unsigned; Smart App Control on
   Windows 11 blocks unsigned programs), the launcher runs the same
   game from source/ under PsychoPy's own Python. The first time it
   installs what PsychoPy lacks into python_packages/ beside it, which
   needs the internet once. Each computer gets its own subfolder there
   (darwin-arm64-py310, win32-amd64-py310), so a folder tested on the
   Mac first still starts clean on the lab PC. Needs PsychoPy with
   Python 3.10 or newer.
5. Log the participant in. The game menu then shows the recording's
   name, for example "EEG: record ActiView as P07_2026-09-24.bdf in
   EEG_Lab/sessions/eeg". Start ActiView's recording with that name in
   that folder, then pick the first game. The line turns to "EEG
   recording ... is in ..." once the file is there. A second login the
   same day gets _2, _3 and so on, so nothing is overwritten.
6. Play the games. Keep Test Mode off in Settings for real data. P
   pauses; Esc twice ends one game. A red "EEG markers lost" means the
   box dropped out: finish that game, then Settings, EEG box, and pick
   it again.
7. End the session with Esc on the game menu, End session. Then stop
   ActiView's recording.
8. Never set 1200 baud anywhere: it resets the box off the bus. The
   game refuses eeg.baud 1200. Leave the port's settings alone.
9. Keep vsync on for the game window, or visual markers lead the
   screen by an unknown amount.
10. Reaction blocks run on a still screen: from code 21 to a second
   after the response only the cued tile changes. Score, streak and
   progress update between trials.
11. Everything lands in sessions/ beside run_in_psychopy.py, whichever
   way the game started: a dated folder per game with trials.csv,
   raw.csv (an eeg row per marker, with the intended and the actual
   send time), metadata.json (eeg section: port, pulse and gap widths,
   box, the code map, latency constants, marker offsets, failure
   counts, degraded flag, and which recording in sessions/eeg the game
   belongs to), events.tsv with events.json, and markers_codes.csv;
   plus rehab.log, the game's own log. Take the whole sessions/ folder
   home and merge it into the project's sessions/: the notebook reads
   the games and lists each game's recording as present or missing.
12. Settings changes made at the lab last until the game closes; every
   launch starts from eeg_lab.yaml again. The trigger box port is the
   one exception, since the port list saves it.
13. Flashing firmware and changing a sensor address are done from the
   exe's Settings screen. The source/ copy carries no avrdude.

Testing the lab build on a Mac, no box
--------------------------------------
scripts/virtual_trigger_box.py stands in for the MMBT-S: a
pseudo-terminal the game opens like any serial port, which records
every byte. It starts the lab folder's source/ under PsychoPy's own
Python with eeg_lab.yaml, the way run_in_psychopy.py does, with
--eeg-port pointed at itself; the hand board is found the normal way.
Play as a participant would, then close the game. The script lists
the bytes it received against the markers each block logged in
raw.csv, in order, and writes the byte log to
EEG_Lab/sessions/eeg/virtual_box_<time>.csv.

    python3 scripts/virtual_trigger_box.py
    python3 scripts/virtual_trigger_box.py --box-only   just the box

The first time, run run_in_psychopy.py once from PsychoPy Coder so it
installs the packages the game needs into EEG_Lab/python_packages.
Delete the test sessions from EEG_Lab/sessions before the folder goes
to the lab.

What the Status channel shows
-----------------------------
- 240 once as the login session's first game starts, 241 once at
  End session or app exit, both outside any block.
- Each block: 200+mode at the start, 20 at GET READY, 220+mode at the
  end (219 if abandoned).
- Each stimulus a 30 to 38 (40 or 41 in pattern blocks, 50 or 51 for
  a syllables option set, 52 for its late prompt buzz), each press
  100 to 131. Every code is held
  8 ms (16 samples at 2048 Hz) then 0. The box's LED flashes on odd
  codes only.
- Pauses are 242 and 243.
- If the box dies mid-session the game keeps going: three failed
  writes, one reopen, then the HUD says "EEG markers lost" and
  metadata marks the block degraded. Behaviour stays valid; ERPs from
  that point do not.

Codes (finger_rehab/hardware/eeg_trigger.py, CODES, version 1.5)
----------------------------------------------------------------
 20  GET READY onset
 21  reaction: wait armed (CNV S1)
 22  rhythm: leading buzz, at the STIM command about 395 ms before the
     beat's own byte (350 lead plus 45 motor rise, then adapting to
     the player), which is then 31
 23  Force Pilot: run start
 24  Force Pilot: section edge, the run's end included
 25  reaction: virtual onset of a catch trial
 30  stimulus, screen only            31  screen + tone
 32  screen + buzz                    33  screen + buzz + tone (default)
 34  uncued                           35  tone only
 36  buzz only                        37  buzz + tone
 38  Buzz Hunt: the buzz is the stimulus, one per trial at its first
     pulse; scored trials write no response byte
 40  pattern block, sequence item     41  pattern block, random item
 50  syllables option set, first attempt
 51  syllables option set, word returned after a miss (four written
     options, nothing names the finger: never pool with the 30 band)
 52  syllables prompt buzz on the right finger, at the STIM command,
     when a set is still unanswered at three quarters of its fall; a
     press after it is a prompted answer
100+lane  correct press               110+lane  wrong finger (lane pressed),
                                          sent at that press; the first
                                          one of a trial is its response
120+lane  false start                 130  timeout (never epoch on it)
131  press with no trial active
140  full ring (hit)  141  open ring (miss)  142  half ring (Late,
     Early, near). Written on the flip that draws the glyph, 800 ms
     after the press, in the modes eeg_lab.yaml names (reaction,
     chords, force_pilot). A glyph the block end cuts short sends no
     byte.
200+mode  block start   219  abandoned   220+mode  block end
     mode ids: reaction 0, classic 1, adaptive 2, rhythm 3, mirror 4,
     pattern 5, chords 6, syllables 7, force_pilot 8, buzz_hunt 10,
     echo 12 (9 retired, 11 reserved)
240  session start   241  session end   242  pause   243  resume
244  rest start      245  rest end

Lanes: 0 to 3 index to little on a one-hand block, whichever hand
(the hand column on the row and in events.tsv says which); with both
hands selected, right 0 to 3 and left 4 to 7. Chords
write one 33 and one response byte per chord, not per finger. Mirror
writes one 33 per pair and one 100+lane per hand, each sent at that
hand's own press. Rhythm's 130 lands when the miss
window closes, inside the next note. Force Pilot runs carry 23 and 24
and no stimulus or response bytes.

For the analysis
----------------
- Every eeg row in raw.csv carries code, t_event (the crossing sample,
  or the flip), t_wire (when the byte left), delayed, failed, dropped
  and name. Response bytes trail the press by 0 to one frame, so
  re-align response-locked epochs to t_event.
- events.tsv (BIDS columns onset, duration, trial_type, value, sample,
  lane, hand, t_event, t_wire, delayed, failed, dropped) is on the
  game's clock, onset from the block's first force sample. Align by
  matching inter-marker intervals to the Status channel, then shift.
  eeg.amplifier_rate_hz in eeg_lab.yaml fills the sample column.
  finger_rehab.hardware.eeg_trigger.export_events(folder) rebuilds the
  three files for any session folder.
- Shift stimulus-locked epochs by eeg.marker_offsets_ms from
  metadata.json: the screen follows the byte by latency.visual_ms
  (20), the tone by latency.tone_ms (12), a felt buzz by
  latency.buzzer_ms (45). Datasheet estimates until the rig is
  measured (latency.measured false); scripts/latency_check.py has the
  bench procedure. Put the medians in the config and in the methods.
- For FRN work drop rows with error_type timeout, device_drop or
  no_signal; 142 (half ring) is neither a win nor a loss. Recordings
  made before 24 September 2026 could carry a 140/141 within one frame of
  the block-end byte: leave that one out. Do not switch
  ui.feedback_style mid-study: it moves the feedback epoch.
- MNE: mne.io.read_raw_bdf(stim_channel="auto") then
  mne.find_events(raw, mask=255, mask_type="and"). EEGLAB: File,
  Import event info, from ASCII file, fields latency type duration.
- Against Welber's old SRT script: it wrote one 30 per flash and
  nothing else. This game puts the cue condition in the byte, so
  epoch on the 30 band, not the literal 30. The old script wrote
  bytes(chr(code), 'UTF-8'), two bytes for anything above 127, and
  held the line 1 to 4 ms; this game writes bytes([code]) and holds
  8 ms on the wall clock. Recordings made under the old prototype map
  (30 = miss, 11 to 18 stimulus) must not be pooled with these.

Validate once before the first real recording. In a Python shell on
the lab PC, `import serial; s = serial.Serial("COM10", 9600);
s.write(bytes([30]))` shows one 30 in ActiView. Then run one reaction
block: the intervals between stimulus bytes in the Status channel must
match the t_wire intervals in raw.csv to within one sample plus 1 ms.
Confirm the ActiView sampling rate with Welber and put it in
eeg.amplifier_rate_hz.
